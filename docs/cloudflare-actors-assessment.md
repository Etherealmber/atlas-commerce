# Cloudflare Actors assessment

[Cloudflare Actors](https://github.com/cloudflare/actors) is a framework on top of Durable Objects, not a replacement for their storage or a fix for a failing upstream database. Its upstream README calls it actively developed; the inspected package reports a beta version. It offers lifecycle helpers, persistence, RPC, alarms and retries, which may be useful for a new isolated feature.

Do not migrate Atlas's existing MobileHub, DemoHub, RestoreHub, NumberHub, AgentQuotaHub or JournalBuffer solely to address error counts. Those classes have existing production bindings, instance IDs, storage, and alarms; changing their identity or semantics risks losing counters, jobs, active sessions or queued journal data. The framework does not automatically migrate any of that state. An adoption proposal should first inventory individual errors, verify package compatibility and maintenance status, and test a new isolated actor in workerd/staging. Any migration of an existing class needs an explicit, reversible data and alarm migration plan, concurrency tests and operational approval. No new Actors dependency is introduced by this assessment.

Dashboard counts alone do not identify the errors or prove an object is unused. Inspect Cloudflare Workers/Durable Object logs by class, timestamp, operation and sanitized error category; avoid publishing request bodies, credentials, or journal contents. JournalBuffer health has owner-only sanitized transfer diagnostics. Expected response codes, platform exceptions, failed downstream requests and alarm failures need separate investigation.
